### 1.2 2进制转8进制和16进制

#### 1.2.1 2进制转8进制

8进制的数字每一位是 0~7 的，0~7 的数字，各自写成2进制，最多有3个2进制位就足够了，比如7的二进制是111，所以在2进制转8进制数的时候，从2进制序列中右边低位开始向左每3个2进制位会换算一个8进制位，剩余不够3个2进制位的直接换算。

如：2进制的 01101011，换成8进制：0153，0开头的数字，会被当做8进制。

#### 1.2.2 2进制转16进制

16进制的数字每一位是0~9, a~f 的，0~9, a~f的数字，各自写成2进制，最多有4个2进制位就足够了，比如 f 的二进制是1111，所以在2进制转16进制数的时候，从2进制序列中右边低位开始向左每4个2进制位会换算一个16进制位，剩余不够4个二进制位的直接换算。

## 2. 原码、反码、补码

整数的2进制表示方法有三种，即原码、反码和补码

1. 有符号整数

有符号整数的三种表示方法均有符号位和数值位两部分，2进制序列中，最高位的1位是被当做符号位，剩余的都是数值位。符号位都是用0表示“正”，用1表示“负”。

![第13章第4页配图](/images/c-language-course/13-p04-fig01.png)

正整数的原、反、补码都相同。

负整数的三种表示方法各不相同，需要进行计算(方法如下)原码：直接将数值按照正负数的形式翻译成二进制得到的就是原码。

反码：将原码的符号位不变，其他位依次按位取反就可以得到反码。

补码：反码+1就得到补码。

📌 有了补码怎么算出原码呢？有2种方法

1. 原路返回：补码-1，再取反，得到原码

2. 补码取反，+1，也能得到原码

所以原码-&gt;补码，补码-&gt;原码 的计算方法是可以统一的。

2. 无符号整数的三种 2 进制表示相同，没有符号位，每一位都是数值位。

![第13章第5页配图](/images/c-language-course/13-p05-fig01.png)

📌 整数存在内存中其实存放的是二进制的补码

为什么呢？

在计算机系统中，数值一律用补码来表示和存储。

原因在于，使用补码，可以将符号位和数值域统一处理；同时，加法和减法也可以统一处理（CPU只有加法器）此外，补码与原码相互转换，其运算过程是相同的，不需要额外的硬件电路。

## 3. 大小端字节序

当我们了解了整数在内存中存储后，我们借助于调试观察整数在内存中存储的一个细节

**课件代码 13-002 · PDF 第 5,6 页**

```c
#include <stdio.h>

int main()
{
    int a = 0x11223344;

    return 0;
}
```

调试的时候，可见在a中的 0x11223344 这个数字是按照字节为单位，倒着存储的。这是为什么呢？

![第13章第6页配图](/images/c-language-course/13-p06-fig01.png)

内存中存储数据的最小单元是1个字节，计算机内存寻址的最小单位也是字节。所以超过1个字节的数据在内存中存储的时候，就有存储顺序的问题，按照不同的存储顺序，我们分为大端字节序存储和小端字节序存储。

小端字节序（存储）模式：

指数据的低位字节内容保存在内存的低地址处，而数据的高位字节内容，保存在内存的高地址处。

![第13章第6页配图](/images/c-language-course/13-p06-fig02.png)

在我们当前的环境下，我们观察到数据就是以小端字节序存储的；小端字节序存储，看起来是“倒着”的，但更符合CPU做加法的自然过程，CPU做加法时，是从最低位开始，并处理进位。如果采用小端序，最低位字节正好存放在最低地址，CPU可以直接拿着最低地址开始算，无需先跳转到高位。小端字节序存储简化CPU硬件设计，提升计算效率。

这种高效性使得小端字节序成为绝大多数主流CPU的选择，例如Intel x86、x86-64和ARM的默认模式（ARM也支持大端，但通常跑小端）。

大端字节序（存储）模式：

指数据的低位字节内容保存在内存的高地址处，而数据的高位字节内容，保存在内存的低地址处。

![第13章第7页配图](/images/c-language-course/13-p07-fig01.png)

人类阅读数字是从左到右、高位到低位，所以大端字节序序直观、符合人类思维。

网络字节序：为了避免不同计算机之间数据传输时发生混乱，TCP/IP协议族规定大端序为“网络字节序”。当数据在网络上传输时，发送方计算机会将数据从其主机字节序转换成网络字节序（大端），接收方再将其从网络字节序转换回自己的主机字节序。

异或运算符的特点：

1. a ^ a = 0（两个相同的数字异或是0）

2. a ^ 0 = 0（任何数字和0异或还是它自己）

3. a ^ b ^ a == a ^ a ^b (异或支持交换律)

代码解释

**课件代码 13-017 · PDF 第 15 页**

```c
#include <stdio.h>
int main()
{
    int a = 10;
    int b = 20;
    a = a ^ b; //a' = a ^ b
    b = a ^ b; //b = a' ^ b = a ^ b ^ b = a
    a = a ^ b; //a = a' ^ b = a ^ b ^ b =  a ^ b ^ a = b
    printf("a = %d  b = %d\n", a, b);
    return 0;
}
```

方法3是正确的，而且不会有溢出。

标志位管理

**课件代码 13-023 · PDF 第 17,18 页**

```c
#include <stdio.h>

// 定义权限标志位（每个权限占一个二进制位）
#define PERM_READ    (1 << 0)  // 0b0001 读权限
#define PERM_WRITE   (1 << 1)  // 0b0010 写权限
#define PERM_EXEC    (1 << 2)  // 0b0100 执行权限
#define PERM_DELETE  (1 << 3)  // 0b1000 删除权限

int main(void)
{
    unsigned char permission = 0;  // 初始没有任何权限

    // ===== 1. 设置标志位 =====
    permission |= PERM_READ;                    // 设置读权限
    permission |= (PERM_WRITE | PERM_EXEC);     // 同时设置写和执行权限

    // ===== 2. 检查标志位 =====
    if (permission & PERM_READ)
    {
        printf("拥有读权限\n");
    }
    if (permission & PERM_WRITE)
    {
        printf("拥有写权限\n");
    }
    if (permission & PERM_EXEC)
    {
        printf("拥有执行权限\n");
    }
    if (permission & PERM_DELETE)
    {
        printf("拥有删除权限\n");
    }

    // ===== 3. 清除标志位 =====
    permission &= ~PERM_WRITE;                  // 清除写权限

    // ===== 4. 切换标志位 =====
    permission ^= PERM_DELETE;                  // 切换删除权限（原来0变1）
    permission ^= PERM_EXEC;                    // 切换执行权限（原来1变0）

    // ===== 5. 输出最终权限状态 =====
    printf("\n=== 最终权限状态 ===\n");
    printf("读权限  : %s\n", (permission & PERM_READ)   ? "开启" : "关闭");
    printf("写权限  : %s\n", (permission & PERM_WRITE)  ? "开启" : "关闭");
    printf("执行权限: %s\n", (permission & PERM_EXEC)   ? "开启" : "关闭");
    printf("删除权限: %s\n", (permission & PERM_DELETE) ? "开启" : "关闭");

    return 0;
}
```
