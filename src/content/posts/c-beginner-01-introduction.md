## 1. 引入：让计算机输出一句话

想让屏幕显示 `Hello, C!`，不能只把这几个字放进一个文本文件。我们需要用 C 的语法描述动作，再由编译工具生成计算机能执行的程序。

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, C!\n");
    return 0;
}
```

运行结果：

```text
Hello, C!
```

C 是一门通用的编译型语言，最初与 Unix 的开发密切相关。它允许直接操作内存，运行开销小，常用于操作系统、嵌入式、驱动和基础库。学习 C 不只是记语法，还要建立“数据如何存放、代码如何执行”的认识。

## 2. 源文件如何变成程序

开发过程可以分成四步：

1. **编写**：在 `.c` 源文件中输入代码，`.h` 头文件通常放接口声明和类型定义。
2. **预处理**：处理 `#include`、`#define` 等指令。
3. **编译**：检查并翻译源代码，生成目标文件（如 `.obj`、`.o`）。
4. **链接**：组合目标文件和所需库，生成可执行文件。

一个多文件工程中，每个 `.c` 分别编译，最后统一链接。Windows 的可执行文件通常是 `.exe`，它与 `.c` 文本文件的用途不同。

| 工具 | 负责什么 | 常见选择 |
| --- | --- | --- |
| 编辑器 | 编辑源代码 | VS Code |
| 编译器 | 翻译代码、报告语法和类型问题 | GCC、Clang、MSVC |
| 链接器 | 组合目标文件和库 | 编译器工具链通常附带 |
| 调试器 | 暂停程序、查看状态、定位错误 | GDB、LLDB、Visual Studio 调试器 |
| IDE | 把编辑、编译、调试集成起来 | Visual Studio、CLion、Xcode |

**Visual Studio 和 VS Code 是不同工具。** VS Code 可以写 C，但安装 C/C++ 扩展并不等于安装了编译器。需要确保编译器、环境变量和调试配置均已就绪。

## 3. 拆解第一个程序

### 3.1 头文件不是函数实现的复制粘贴

`#include <stdio.h>` 让编译器看到标准输入输出接口的声明，`stdio` 可以理解为 standard input/output。使用库函数前，应包含它对应的头文件，不依赖“编译器似乎知道这个函数”。

### 3.2 main 是入口函数

```c
int main(void)
{
    return 0;
}
```

- `int` 表示返回整数状态。
- `main` 是通常的宿主环境下程序入口。
- `void` 明确表示没有参数。
- `{}` 包围函数体。
- `return 0;` 表示成功结束，将状态返回给运行环境。

不要把标准入口写成 `void main()`。一个可执行程序应有一个入口定义；在同一工程中留下多个练习用 `main`，通常会导致重复定义的链接错误。

### 3.3 printf 的基本形式

```c
printf("姓名：%s，年龄：%d\n", "Lin", 18);
```

双引号中的内容是格式字符串，`%s` 对应字符串，`%d` 对应 `int`。`\n` 是换行。占位符的数量和类型都应与后面的参数匹配。

语句末尾通常写 `;`，但预处理指令不是普通语句，`#include <stdio.h>` 后面不需要分号。

## 4. 案例：输入两个整数并求和

先描述流程：准备两个变量 → 从键盘读取 → 计算 → 输出。读入成功后才能使用输入结果。

```c
#include <stdio.h>

int main(void)
{
    int a = 0;
    int b = 0;

    printf("输入两个整数：");
    if (scanf("%d %d", &a, &b) != 2) {
        printf("输入失败，需要两个整数。\n");
        return 1;
    }

    printf("%d + %d = %d\n", a, b, a + b);
    return 0;
}
```

输入 `12 8`，结果是 `12 + 8 = 20`。`scanf` 需要变量的地址，因此这里用 `&a`、`&b`；其返回值是成功赋值的项目数。暂时把 `&` 理解为“告诉函数把数据写到哪里”，第 11 篇会专门讲地址。

此例假定两个输入及其和均在 `int` 范围内。后续处理真实输入时，还要考虑数值范围，而不只是格式是否匹配。

使用 MSVC 时，可能看到关于 `scanf` 的 C4996 提示。它属于该工具链的安全诊断策略，不代表标准 C 中没有 `scanf`；也不要把 MSVC 专有接口当成所有平台都具备的函数。

## 5. 注释、语法和排错习惯

```c
// 单行注释：解释目的或约束

/* 多行注释。
   不要把这种注释嵌套使用。 */
```

注释解释“为什么这样做”，变量名和代码负责表达“做什么”。C 区分大小写，`Main` 与 `main` 不相同；中文全角分号 `；`、引号 `“”` 不能替代 C 语法中的 ASCII 符号。

常见错误可按发生阶段区分：

| 现象 | 优先检查 |
| --- | --- |
| 编译报错 | 分号、括号、拼写、类型、头文件 |
| 链接报错 | 函数是否有定义、源文件是否加入工程、是否重复定义 |
| 运行结果错误 | 条件、计算公式、输入状态、边界 |
| 程序异常退出 | 越界、无效地址、除零等 |

先读第一条有意义的错误，后面的错误可能只是连锁反应。一次只改少量代码，重新编译验证，不要同时修几十处“猜测中的问题”。

## 6. 自测

1. `.c` 文件为什么不能直接当作可执行程序运行？
2. `printf("%d", 10);` 中哪部分是格式字符串，哪部分是数据？
3. 给求和程序增加一行输出，显示 `a - b`，并测试负数输入。

掌握标准：能独立创建、编译和运行一个程序，并区分编译、链接和运行三个阶段。
