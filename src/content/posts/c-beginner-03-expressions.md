## 1. 引入：为什么平均值会丢小数

三个人均分 10 元，数学结果是 3.333…，但下面的程序输出 `3.000000`：

```c
double average = 10 / 3;
printf("%f\n", average);
```

原因不是 `double` 不支持小数，而是 `/` 两边都是整数，先做整数除法得到 3，再转换成 `double`。目标变量类型不会倒过来改变已经完成的运算。

```c
double a = 10.0 / 3;       // 运算前已有浮点操作数
double b = (double)10 / 3; // 先转换，再除
double c = (double)(10 / 3); // 已经丢失小数，只能得到 3.0
```

## 2. 算术操作符与取余

`+ - * / %` 分别用于加、减、乘、除、取余。前四种支持整数和浮点数，`%` 只支持整数。整数除法从 C99 起向 0 截断，例如 `-7 / 3 == -2`，`-7 % 3 == -1`。

在商可表示且除数非零的前提下，整数满足：

```text
a == (a / b) * b + a % b
```

除数不能为 0。常见补码实现上 `INT_MIN / -1` 也会因结果不可表示而产生未定义行为。

### 案例：拆出十进制数字

整数 `% 10` 得个位，`/ 10` 去掉个位。这是拆数字、判断回文数等题目的基础。

```c
#include <stdio.h>

int main(void)
{
    int number = 507;
    printf("百位：%d\n", number / 100);
    printf("十位：%d\n", number / 10 % 10);
    printf("个位：%d\n", number % 10);
    return 0;
}
```

这里限定输入为三位非负整数。`507 / 10` 先得 50，再 `% 10` 得 0。将适用范围写清楚，比依靠少量测试“看起来对”更可靠。

## 3. 赋值与复合赋值

```c
int count = 1;
count = 5;
count += 2; // 变成 7
count *= 3; // 变成 21
```

`=` 表示把右侧表达式的值转换为左侧类型并存入左侧对象，不能把它理解为数学中的相等关系。判断相等用 `==`。`a = b = 0` 按右结合解析为 `a = (b = 0)`，但连续赋值应适度使用，优先保证可读性。

复合赋值包括 `+= -= *= /= %=`，后续还有位运算版本。`x += y` 的效果类似 `x = x + y`，但左侧表达式只求值一次；有副作用的左侧不能机械地展开替换。

```c
int x = 3;
x += 2.8; // 计算后转换回 int，结果为 5
```

赋值可能丢精度。转换前应确认范围，不要依靠超出可表示范围的浮点转整数操作。

## 4. 前置与后置自增

| 表达式 | 动作 | 表达式本身的值 |
| --- | --- | --- |
| `++i` | 先使 i 加 1 | 增加后的值 |
| `i++` | 使 i 加 1 | 增加前的值 |
| `--i` | 先使 i 减 1 | 减少后的值 |
| `i--` | 使 i 减 1 | 减少前的值 |

```c
int i = 3;
int a = i++; // a = 3，i = 4
int b = ++i; // i = 5，b = 5
```

独立写成 `i++;` 和 `++i;` 时，语句完成后的 `i` 相同。差别体现在使用表达式结果的场景。不要把“先使用再加一”误读成整个大表达式结束后才更新；副作用的求值顺序要遵循语言规则。

单目 `+`、`-` 是正号和负号，例如 `-x`；它们与双目加减法的操作数个数不同。

## 5. 优先级、结合性、求值顺序是三件事

```c
int a = 2 + 3 * 4;   // 2 + (3 * 4)，得到 14
int b = (2 + 3) * 4; // 20
int c = 20 / 5 * 2;  // (20 / 5) * 2，得到 8
```

- **优先级**：表达式怎样分组，如乘法先与其操作数结合。
- **结合性**：同优先级操作符怎样分组，如乘除左结合、赋值右结合。
- **求值顺序**：子表达式实际先后执行的顺序。

优先级和结合性不能推导所有运行顺序。`f() + g()` 并不保证先调用 `f`；`printf("%d %d", f(), g())` 的两个实参也没有固定的左右求值顺序。加括号能改变分组，但通常不能强制实参的求值顺序。

## 6. 整型提升与通常算术转换

较小整数类型参与多数运算时，会先整型提升。若 `int` 能表示原类型全部值，提升为 `int`，否则提升为 `unsigned int`。

```c
unsigned char a = 200;
unsigned char b = 100;
int result = a + b; // 常见 32 位 int 平台上先提升为 int，结果为 300
```

整数与浮点混合运算时，通常会转换到共同类型，例如 `3 + 0.5` 得到 `double` 结果 `3.5`。但不能简单概括为“永远向字节更多的类型转换”，带符号和无符号混合时规则与等级、可表示范围有关。

```c
int a = -1;
unsigned int b = 1;
printf("%d\n", a < b); // 0：a 转成 unsigned int 后成为很大的值
```

这也是长度类型 `size_t`（无符号）参与减法和比较时的常见陷阱。`strlen(s) - 1` 在空字符串上会下溢；先判断长度是否大于 0，再做减法。

强制转换如 `(double)a` 只转换这次表达式的值，不会改变变量 `a` 的声明类型。转换是明确意图的工具，不能替代范围检查。

## 7. 不要用问题表达式考验编译器

```c
// 以下是错误示例，不要运行来猜答案：
// i = i++ + ++i;
// printf("%d %d", i++, i++);
```

同一个标量对象上的修改与修改、修改与读取，如果没有要求的先后关系，可能构成未定义行为。此时不是“不同编译器有不同正确答案”，而是语言不再保证结果。

把动作拆开，意图就清楚了：

```c
int i = 3;
int before = i;
++i;
printf("原值：%d，新值：%d\n", before, i);
```

还要警惕有符号溢出、除零和使用未初始化变量。编译器警告、调试器和 Sanitizer 都能辅助发现问题，但不能把某次输出当作语言规则。

## 8. 练习

1. 预测 `5 / 2`、`5 / 2.0`、`(double)(5 / 2)`：分别为 2、2.5、2.0。
2. 用 `/` 和 `%` 将 3678 秒拆成时、分、秒：1 小时 1 分 18 秒。
3. 写计算两次考试平均分的函数，确认奇数总分不会因整数除法丢失 0.5。
4. 遇到复杂自增表达式时，将每次状态修改拆成独立语句，再说明代码真正想完成什么。
